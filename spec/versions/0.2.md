# PSL Version 0.2

PSL v0.2 extends the language for real-world coaching workflows while preserving v0.1 compatibility.

## Scope (Roadmap v0.2: Language Growth)

### Must

1. Stable exercise identity (`exercise_id`) and alias normalization (`exercise_aliases`, `aliases`).
2. Set roles + role-referenced intensity (`percent_of_set`, `load_delta_from_set`).
3. Time-based set model (`work_type`, `time_mode`, duration/interval/target).
4. Grouping/rest loci (`session.groups`, `exercise.group_id`, rest inheritance).
5. Declarative constraints/repeat (`constraints`, `repeat`) with shorthand caps/stop clauses.
6. Progression growth shape (`scope`, `criteria.aggregation`, `auto_adjust`, action objects).
7. Deload/fatigue modifiers (`deload`, `volume_multiplier`, `intensity_cap`, `exercise_swap_map`).
8. Multi-session day slotting (`session.slot`).

### Should

1. Exercise families/tags/substitutions (`family`, `tags`, `substitutions`).
2. Top-level and per-exercise units/rounding (`units`, `rounding`).
3. Tempo/execution metadata (`tempo`, `pause_seconds`, `eccentric_seconds`).
4. Improved shorthand diagnostics with line-aware paths.

### Could (Declarative in v0.2, runtime later)

1. Non-increment progression actions (`repeat_week`, `reduce_volume`, `switch_variant`).
2. Aggregated progression conditions (`total_reps`, `avg_rpe`, `min_load`).
3. Velocity-loss constraints for VBT integrations.

## v0.2 Spec Delta

Canonical AST is represented by `src/ast/types.ts`. New/updated fields:

- Top-level:
  - `language_version: "0.1" | "0.2"`
  - `units?: "kg" | "lb"`
  - `rounding?: { round_to?, mode?, equipment? }`
  - `exercise_aliases?: Record<string, string>`
- Session:
  - `slot?: "AM" | "PM" | "EVE" | number`
  - `rest_default_seconds?: number`
  - `groups?: SessionGroup[]`
  - `constraints?: PrescriptionConstraints`
  - `modifiers?: { deload?, volume_multiplier?, intensity_cap?, exercise_swap_map? }`
- Exercise:
  - `exercise_id?: string`, `aliases?: string[]`
  - `family?: string`, `tags?: string[]`, `modifiers?: Record<string,string>`
  - `substitutions?: ExerciseSubstitution[]`
  - `constraints?: PrescriptionConstraints`
  - `warmup?: WarmupSpec`
  - `group_id?: string`
  - `rest_before_seconds?`, `rest_after_seconds?`
  - `tempo?`, `pause_seconds?`, `eccentric_seconds?`
  - `units?`, `rounding?`
- Set:
  - `work_type?: "reps" | "time"`
  - `time_mode?: "amrap" | "emom" | "for_time" | "density"`
  - `duration_seconds?`, `interval_seconds?`, `target_total_reps?`
  - `role?: SetRole`
  - `rest_before_seconds?`, `rest_after_seconds?`
  - `constraints?: PrescriptionConstraints`
  - `repeat?: { max_sets?, until? }`
  - `tempo?`, `pause_seconds?`, `eccentric_seconds?`
- Intensity:
  - Added `percent_of_set { role, value }`
  - Added `load_delta_from_set { role, value, unit }`
- Progression:
  - Added `scope?: "set" | "exercise" | "session"`
  - Added `criteria?: { aggregation?, condition? }`
  - Added strategy `auto_adjust { criteria, actions[] }`
  - Added actions: `repeat_week`, `reduce_load`, `reduce_volume`, `switch_variant`
- Completion results (backward-compatible extension):
  - `exercise_id?: string` on exercise completion entries
  - `reps_completed?: number` on set completion entries

## Examples (Structured + Shorthand)

### 1) Powerlifting top + backoff with warmups

Structured:

```yaml
- exercise: Competition Squat
  exercise_id: squat_comp
  warmup:
    type: percent_ramp
    from_percent: 40
    to_percent: 85
    steps: 4
    reps: 3
    based_on_role: top
  sets:
    - count: 1
      reps: 1
      role: top
      intensity: { type: rpe, value: 8 }
    - count: 3
      reps: 3
      role: backoff
      intensity: { type: percent_of_set, role: top, value: 88 }
```

Shorthand:

```yaml
- exercise: Competition Squat
  sets: |
    1x1 @RPE8 role top
    3x3 @-12% backoff
```

### 2) Bodybuilding giant set with group rest

Structured:

```yaml
groups:
  - id: A
    type: giant_set
    rounds: 3
    rest_between_rounds: 2m
exercises:
  - exercise: Cable Fly
    group_id: A
    sets: ["1x15 @RIR2 work"]
  - exercise: DB Lateral Raise
    group_id: A
    sets: ["1x20 @RIR2 work"]
  - exercise: Rope Pushdown
    group_id: A
    sets: ["1x15 @RIR2 work"]
```

Shorthand:

```yaml
exercises: |
  A1 Cable Fly: 1x15 @RIR2
  A2 DB Lateral Raise: 1x20 @RIR2
  A3 Rope Pushdown: 1x15 @RIR2
```

### 3) Density / AMRAP finisher

Structured:

```yaml
sets:
  - count: 1
    work_type: time
    time_mode: amrap
    duration_seconds: 480
    intensity: { type: rpe, value: 8 }
    constraints: { max_total_reps: 12 }
  - count: 1
    work_type: time
    time_mode: density
    duration_seconds: 480
    target_total_reps: 30
```

Shorthand:

```yaml
sets:
  - "AMRAP 8m @RPE8 cap12"
  - "density 8m target 30 reps"
```

### 4) Progression with aggregation

Structured:

```yaml
progression:
  type: auto_adjust
  scope: exercise
  criteria:
    aggregation: all_sets
    condition:
      type: metric_vs_target
      metric: load
      op: ">="
      target: max
  actions:
    - type: reduce_load
      by: { value: 2.5, unit: kg }
```

Shorthand (increment-compatible path):

```yaml
progression: "+2.5kg every week if load>=target"
```

### 5) Deload block modifier

Structured:

```yaml
blocks:
  - id: deload
    duration: "1w"
    deload: true
    exercise_swap_map:
      squat_comp: squat_paused
    sessions: []
```

Shorthand-like inline sugar (same fields at session/block scope):

```yaml
deload: true
volume_multiplier: 0.6
intensity_cap: { max_rpe: 7 }
```

## Validation Additions (Ambiguity/Contradiction Guards)

1. Role reference must point to a prior set role in the same exercise.
2. `work_type: reps` rejects time-only fields (`duration_seconds`, `interval_seconds`, `target_total_reps`).
3. `EMOM` requires `reps`; missing interval warns (60s default).
4. `repeat.max_sets` cannot exceed `constraints.max_sets`.
5. `progression.when` and `progression.criteria.condition` are mutually exclusive.
6. `aliases` requires `exercise_id`.
7. Duplicate/unknown `group_id` values are rejected.

## Runtime Boundaries (v0.2 vs v0.3)

- Implemented at runtime in v0.2:
  - Increment-style progression (`increment`, `weekly_increment`) using completion results.
  - Deload deterministic transforms in compilation (`volume_multiplier`, `intensity_cap.max_rpe`, `exercise_swap_map`).
- Declarative only in v0.2 (shape + validation + compilation output):
  - `auto_adjust` progression criteria/actions
  - `repeat.until` runtime termination logic
  - role-referenced load realization (`percent_of_set`, `load_delta_from_set`)
  - substitution selection logic

## Migration (v0.1 → v0.2)

1. No rewrite required: all valid v0.1 documents remain valid.
2. Keep `language_version: "0.1"` for frozen docs; use `"0.2"` for new features.
3. Prefer adding `exercise_id` now for stable analytics/interoperability.
4. Move ad-hoc notes to structured fields (`role`, `groups`, `constraints`, `repeat`) incrementally.
